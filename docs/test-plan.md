# Тест-план Витте-Дашборд

## 1. Идентификатор тест-плана (Test plan identifier)
`TP-MVD-2026-01`, версия 1.0, дата 23.11.2026.

## 2. Введение (Introduction)
План определяет объём, подходы, ресурсы и график тестирования модуля визуализации данных Витте-Дашборд
(веб-приложение для единого центра статистических данных ЧОУ ВО «Московский университет им. С.Ю. Витте»).
Основание — техническое задание (раздел 1.7 отчёта) и приложение к индивидуальному заданию на практику.

## 3. Объект тестирования (Test items)
Сборка из ветки `master` репозитория `vitte`: Flask-приложение (`app/`), база данных PostgreSQL
(`sql/create_tables.sql`, `sql/insert_test_data.sql`), модуль интеграции с 1С (`app/services/onec.py`),
экспорт отчётов (`app/services/exporter.py`).

## 4. Функции, которые будут протестированы (Features to be tested)
1. Публичные страницы, меню, «хлебные крошки», форма обратной связи, подвал с ФИО автора.
2. Аутентификация, выход, защита от CSRF, перенаправления.
3. Ролевая модель: Администратор, Руководство, УМУ, Деканат; ограничение данных по факультету.
4. Дашборды и JSON-API, фильтры периода и факультета, кэш агрегатов.
5. Формирование отчётов XLSX, DOCX, CSV.
6. Личный кабинет: профиль, пароль, история отчётов, файлы, настройки.
7. Панель администратора: пользователи, факультеты, показатели, новости, обращения, аудит.
8. Интеграция с 1С: загрузка данных, проверка формата, журнал синхронизации.
9. Нефункциональные требования: время формирования данных ≤ 5 с, работа 10 пользователей без деградации,
   адаптивность, безопасность.

## 5. Функции, которые не будут протестированы (Features not to be tested)
- Работа с реальной базой 1С:Предприятие университета (нет доступа; используется файл-эмулятор формата ответа).
- Экспорт в PDF на стороне сервера (реализован печатью страницы браузером).
- Тестирование в Яндекс.Браузере и Firefox вручную (проверены Chromium-движок и логика сервера; кросс-браузерная
  проверка включена в рекомендации по опытной эксплуатации).
- Стресс-тестирование свыше 30 одновременных пользователей и тестирование надёжности длительностью более суток.

## 6. Тестовые подходы (Approach)
Применяются не менее четырёх групп методов (выбраны 8):

| Группа | Метод | Как применяется |
|---|---|---|
| По принципам работы | Позитивное и негативное | корректные и некорректные данные форм, файлов, выгрузки 1С |
| По уровню функционального | Смоук, критический путь, расширенное | открытие всех страниц; вход → дашборд → отчёт; проверка всех требований |
| По целям | Функциональное, нагрузочное, безопасности, GUI/UI | pytest, `tools/load_test.py`, SQL-инъекция/CSRF/open redirect, просмотр на ПК и смартфоне |
| По запуску кода | Статическое и динамическое | анализ pyflakes; запуск автотестов и ручные проверки |
| По доступу к коду | Белый и чёрный ящик | автотесты с доступом к БД и коду; ручная работа через интерфейс |
| По детализации | Модульное, интеграционное, системное | сервисы (`onec`, `exporter`), связка Flask + PostgreSQL, сквозные сценарии |
| По автоматизации | Ручное и автоматическое | 172 автотеста pytest + ручные сценарии в браузере |
| Повторное | Регрессионное и подтверждающее | `tests/test_regression.py` для исправленных дефектов |

## 7. Критерии прохождения тестирования (Item pass/fail criteria)
- Все автотесты проходят (0 падений), критических (S1–S2) открытых дефектов нет.
- Время ответа типового запроса данных дашборда — не более 5 секунд при 10 пользователях.
- Каждая из 15 публичных страниц открывается с кодом 200 и содержит «хлебные крошки».
- Деканат не получает данные чужих факультетов ни через интерфейс, ни через API.

## 8. Критерии приостановления и возобновления (Suspension criteria and resumption requirements)
Приостановка: приложение не запускается; недоступна БД; падает более 20 % автотестов смоук-набора.
Возобновление: после исправления блокирующего дефекта и успешного прохождения смоук-набора.

## 9. Результаты тестирования (Test deliverables)
Тест-план, тест-кейсы (`docs/test-cases.md`), баг-репорты (`docs/bug-reports.md`), протокол запуска автотестов
и отчёт о нагрузочном тестировании (`docs/test-results.md`).

## 10. Задачи тестирования (Testing tasks)
Подготовка тестовой БД и данных → смоук-тестирование сборки → разработка и запуск автотестов → ручные сценарии →
нагрузочное тестирование → статический анализ → фиксация дефектов → исправление → регрессионное тестирование.

рабочая станция: Intel Core i5, 16 ГБ ОЗУ.
